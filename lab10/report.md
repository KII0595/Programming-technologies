## Часть 1: API для управления книгами (FastAPI + Python)

### Структура проекта
```
fastapi-book-api/
├── main.py
├── models.py
├── routers.py
├── requirements.txt
└── README.md
```

### Реализованный функционал
- Полноценный CRUD операций
- Фильтрация и пагинация (GET /books)
- Заимствование и возврат книг
- Проверка уникальности ISBN
- Статистика библиотеки (GET /stats)
- Обработка ошибок (404, 400)
- Автоматическая документация Swagger UI

#### Основные эндпоинты:
- `GET /api/v1/books` — список книг с фильтрами
- `POST /api/v1/books` — добавление книги
- `POST /api/v1/books/{id}/borrow` — заимствование
-  `POST /api/v1/books/{id}/return` — возврат
-  `GET /api/v1/stats` — статистика

#### Запуск:
```bash
cd fastapi-book-api
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python main.py
```

## 📋 Ответы на контрольные вопросы

### Часть 1: FastAPI

1. **Преимущества Pydantic моделей:**
   - Автоматическая валидация данных
   - Генерация JSON Schema и документации
   - Поддержка типов Python
   - Защита от некорректных данных
   - Удобное преобразование (`model_dump()`, `exclude_unset`)
  
2. **Автоматическая документация:**
   FastAPI автоматически генерирует OpenAPI спецификацию на основе типов, моделей Pydantic и docstring. Доступна через Swagger UI (`/docs`) и ReDoc (`/redoc`).

3. **Почему важна уникальность ISBN?**
   **ISBN** — международный стандартный идентификатор книги. Дублирование приведёт к конфликтам данных и нарушению бизнес-логики.

4. **Использованные HTTP статус-коды:**
   - `201` — создание ресурса
   - `204` — успешное удаление (без тела ответа)
   - `400` — ошибка валидации / бизнес-логика
   - `404` — ресурс не найден
  
### Часть 2: Express

1. **Использованные middleware:**
   - **Helmet** — безопасность (заголовки)
   - **express-rate-limit** — защита от DDoS
   - **CORS** — разрешение кросс-доменных запросов
   - **Joi** — валидация входящих данных
   - Кастомные: `errorHandler`, `notFoundHandler`

2. **Joi vs Pydantic:**
   - **Pydantic** — глубже интегрирован с Python, работает с типами, лучше для автодокументации.
   - **Joi** — очень гибкий, отличные сообщения об ошибках, популярен в JS-экосистеме.

3. **Преимущества файлового хранения:**
   - Простота реализации
   - Не требует установки БД
   - Удобно для обучения и прототипирования

4. **Улучшения для production:**
   - Переход на базу данных (PostgreSQL / MongoDB)
   - Docker + docker-compose
   - Аутентификация (JWT)
   - Логирование (Winston)
   - Тесты (Jest / Supertest)
   - CI/CD
